# DSH-board 规格

实现状态：§1–§11 保留既有实现与验证记录；§12 描述按聊天编辑权限及紧凑菜单；§13 描述有序自由曲线；§14 描述 0.1.10-dev.5 的箭头与线尾衔接。真实模型试用验收另行记录。

## 1. 项目边界

DSH-board 是 DSH web profile 的本地白板协作插件；draft-board 是白板界面、文件格式和模型的真源。插件从上游 `c37c6fe` 拆出，独立发布试用版 0.1.5。数据与交互契约沿用 upstream.json 锁定源码中的 docs/spec.md；公开基线见 [上游规格](https://github.com/MYming-yue/draft-board/blob/main/docs/spec.md)，本地未发布提交见 §13–§14。本项目不重复定义节点、关系、集合、操作和历史语义。

目标宿主为 DSH CLI 0.1.5-rc.1、组合包 0.1.5-rc.2、web profile；实际宿主联调为 Windows Chrome。其他组合未经完整验证。

## 2. 界面与消息

完整白板在左、原生对话在右；对话可收起，分隔线可通过鼠标或键盘调整宽度。布局通过 `shell.overlay` 添加，原生对话仍由 DSH 渲染；使用当前 AppFrame 中心列适配，不移动或接管其 React 节点。会话容器替换后重新挂接；中心列皮肤装饰限定在聊天区域。

发送瞬间捕获所选卡片的身份与至多 80 字符短标题，不附上正文／备注，不改写用户回复。通过原生 admission requestId 单独提交元数据；消息被 claim 时成为本轮关联，之后的选区变化不改写它。复用原生附件、echo、queue／steer 与取消流程。未关联的新回复清除旧关联，更换白板忽略旧身份。

固定协作说明和用户可编辑的使用方法（§8）在系统提示末尾，动态关联作为 `systemPrompt.context` 的末尾贡献，由 DSH 在已接受消息之后注入。关联无时间戳、修订号或模型可见消息 ID；相同关联文本一致，依赖原生快照去重。保留既有前缀与历史，不宣称零历史开销或固定缓存命中率。

## 3. 当前草稿与编辑

默认数据目录为 `DSH_HOME/dsh-board`，未设置 DSH_HOME 时使用 `~/.dsh/dsh-board`；宿主 composition 可用 dataDir 覆盖。`boards/<uuid>.draft` 保存 ZIP、内嵌资源与完整历史，`current.json` 指向当前文件。新开／切换聊天沿用当前草稿，白板“新建”／“打开”主动更换时保留旧文件。

`draft_board_read` 提供结构、文本与内容版本；`draft_board_apply` 接受 JSON 编码的上游 AgentBatch，使用真实身份、版本、原子校验与历史，不允许 shell 绕过。一个批次是一轮，既有更新标记与整轮撤销适用。图片资源保留，当前不新增图片视觉解析工具。

同源 API 约每 750ms 镜像已提交内容。浏览器快照携带进程代际和修订号，过期写入拒绝；输入、指针、布局、保存或回放期间保留操作。AI 更新保留视角，只有上游历史可验证的追加变化自动接收。冲突保留双方内容、暂停镜像，可另存为后重新打开副本明确更换。

宿主副本与原生磁盘文件句柄分别管理；AI 更新已绑定文件后仍显示未保存，不能将副本已更新当作原文件已保存。首次加载前阻止空白板编辑；嵌入模式不注册白板 Service Worker。

## 4. 管理

原生设置页入口“DSH-board 白板”，有 enabled 与 associateSelection 两项布尔选项。关闭共同白板恢复完整聊天布局、注销白板工具和提示；管理入口、草稿及隐藏页面的未提交输入保留。再次启用沿用当前草稿。关联选项变化不重新注册稳定工具或固定说明。

`plugin-state.json` 保存选项、待处理关联与当前关联，重启后恢复。关联元数据不写入 `.draft`，不形成独立任务系统。选项 API 只允许修改插件自己的两项布尔选项；使用方法走独立的固定文件 API（§8），不修改 DSH 模型、凭据、MCP 或皮肤配置。

## 5. 独立构建与分发

upstream.json 保存公开上游 URL 与完整 40 字符提交 SHA。构建创建受管理的 `.upstream/draft-board` 缓存，核对远端、提交和目录边界；拒绝接管其他 checkout 或丢弃本地修改。依赖使用上游 package-lock.json；没有相邻目录或开发者磁盘路径依赖。

lib 包含上游编译的白板页面、共享模型、原生客户端适配、上游来源锁与许可证、运行依赖许可证声明。Release tgz 包含可运行产物，安装时无需重新获取或构建上游。源码仓库不提交生成的 lib、缓存、个人配置或草稿。

构建和打包不得读取个人 DSH home。更换上游提交需重新验证；修改白板业务语义应在上游实现，不在插件复制模型规则。插件拆仓库不改变原有 `.draft` 格式或数据目录。

## 6. 验证

`npm run check` 包含独立构建、Node 插件测试和安装包浏览器检查。测试覆盖批次原子性、版本与代际冲突、草稿切换／重启、消息正文保留、排队关联、稳定上下文、管理停用与保留草稿。

安装包检查用本次唯一临时目录和合成草稿，从真实 tgz 解压启动宿主 API，加载包内白板页面，接收批次并整轮撤销，验证包中不存在本地上游路径依赖。模型 API、真实 DSH 附件／审批和其他宿主版本仍需实际联调。任何失败或未验证范围应如实记录，不删断言制造通过。

## 7. AI 布局任务（0.1.6-dev.1，2026-10-12 开发预览）

### 7-A. 权限与目标

布局整理与卡片／关系／集合创建为独立任务。模型读取语义与现有结构，自主决定布局；提交仅包含已有卡片身份和坐标。禁止改变文字、备注、尺寸、颜色、展开状态、关系、集合成员及增删实体。

固定白板说明不随任务改变；仅在已接受的布局消息所属 Agent 本轮运行上下文尾部贡献布局专用规则。默认风格清晰、克制、留白适度：层级、对比、推导及跨组联系容易阅读，组内紧凑、组间留白、对齐有秩序、整体均衡，考虑窗口比例与可读性；保留合理现有布局，少做无意义移动。审美是软目标，范围、版本和几何为硬约束。卡片文字作为数据，不作为任务指令。

### 7-B. 原生任务接线

嵌入页面“AI 布局整理”普通点击为全板，Shift 点击为选中卡片及父子后代。页面先同步已提交内容，发送 boardId、baseContentVersion、宿主 revision、全板 DOM 实测外框、画布宽高及允许移动的身份列表。宿主客户端解析当前原生 SessionBinding，通过 Conversation.sendSession 提交一条明确的布局请求，附件列表为空，不消费原输入框的文字或待发附件，不另配 API、不创建隐藏模型服务。

布局快照单独 POST 至插件 API，用原生 sessionId 和 admission requestId 绑定；用户可见消息不附正文或几何 JSON。排队消息在 agent/inbox/claimed 时进入任务模式；只有匹配的 Agent 可以读取／提交。原生拒收则取消待处理任务；丢失响应时保留任务身份供查询或取消，不假定消息未被接受。

一个白板同时只允许一个 pending／running 布局任务，状态为 pending → running → completed／failed／cancelled。Agent 本轮工具可见性缩小为布局读取和提交，执行 guard 阻止其他工具调用；保留原生 run_code 传输，其嵌套调用仍经工具 guard。另一会话的普通编辑不受此工具掩码影响，但其内容更新会使旧布局版本失效。取消的排队请求被 claim 后仍受限制，不能通过通用编辑接口继续工作。

任务成功后本轮仍受限制，防止顺带修改内容。Agent idle／下一条原生用户消息结束任务模式并恢复普通工具；本轮未成功提交则标记失败。关闭插件取消任务并恢复原生工具流程。任务记录仅存内存，不写入草稿或插件状态；宿主重启后旧任务不可提交。恢复的原生工具栏请求若没有对应快照，本轮仍限制为布局工具，提示重新整理，不能回退到通用编辑。

### 7-C. 受限工具与候选校验

`draft_board_layout_read` 参数为空，只对当前布局 Agent 返回 taskId、boardId、baseContentVersion、允许移动的 nodeIds、全板内容／边／集合、geometry、viewport 和剩余尝试次数。

`draft_board_layout_apply` 仅接受 `{taskId, boardId, baseContentVersion, positions:[{nodeId,x,y}]}`。拒绝额外字段、重复或超范围身份、非有限坐标及绝对值超过 10,000,000 的坐标。原生运行身份决定任务归属，不接受调用方自报会话身份。

候选先在内存中用上游原子批次应用为 moveNode，再用共享几何检查卡片至少 10 世界单位间距、非成员卡片与集合边界、自动绕行后连线与非端点卡片及关系说明遮挡。局部任务忽略完全不涉及允许移动卡片的旧冲突。失败返回具体冲突和剩余次数，不修改文件、修订号或历史；最多 3 次候选尝试。所有有效移动同一步提交，沿用真实 before、版本递增与整轮撤销。空或实际无变化的 positions 直接完成且不新增历史。

白板更新、身份／内容版本／进程修订变化拒绝旧候选；卡片显示外框或画布宽高相对任务快照变化，经页面约 750ms 报告后使任务失效。版本与布局提交共用串行写入队列。取消信号在原子文件重命名前生效；重命名已完成即视为提交成功，随后完成指针与内存发布，不制造已落盘而内存未更新的状态。

`E_LAYOUT_TASK`、`E_LAYOUT_GEOMETRY` 是插件任务层结果，不增加上游模型错误码。正文编辑继续使用原有 `draft_board_read`／`draft_board_apply`，不复用布局提交入口。

### 7-D. 验证

单测覆盖 admission 身份、拒收与丢失响应、任务工具范围与退出、局部范围、非法字段／坐标、候选失败不落盘、三次上限、并行版本变化、显示变化、取消排队任务、无变化无历史与单批提交。解压安装包浏览器检查验证实际尺寸快照、宿主桥接、受限提交、镜像接收和一次撤销。真实 DSH 还需验证当前对话绑定、工具 guard／掩码与实际模型输出；审美质量由用户测试反馈继续迭代，不以合成宿主回归宣称保证。

0.1.6-dev.1 的本机修改已由用户于 2026-10-14 确认验收；后续方法提示词改动不修改本节的布局权限或算法。

### 7-E. 布局任务的呈现（0.1.7-dev.2）

布局仍使用当前模型、原生 admission 和原生消息历史；只是 Web 展示改为白板侧状态浮层与紧凑任务入口。新 admission 的正文缩短为“✦ 整理白板布局”，详细规则放本轮运行上下文，不在原生排队预览中重复长指令；既有长请求保持历史原文并兼容收起，重启后无快照仍受布局工具限制。插件通过 `conversation.chat.node` 原生 keyed 注册的优先级机制包装现有渲染器，保留其 locale、inject 和普通消息渲染，不编辑宿主文件或既有历史。精确的单段工具栏请求默认收起，不通过“包含布局字样”匹配普通消息；布局请求所在原生 turn 的思考、模型输出和注入上下文默认收起。无法确认归属、历史不完整或同 turn 存在普通 user／steer 时输出保持原生可见。用户可点“查看过程”展开指令与原生输出；原生错误、重试、审批、停止与轨迹入口不隐藏。停用插件恢复原生呈现。

白板下方非阻塞浮层展示 submitting／pending／running／completed／cancelled／failed 真实状态，不模拟百分比或虚构阶段。pending 显示排队原因，运行中提供微光、卡片呼吸与慢速轨道动画；已提交后显示实际移动数量或无需调整，6 秒自动收起。失败不自动消失，保留原因与手动收起按钮。取消沿用布局 API 的提交取消；模型停止仍由原生控制。减少动态效果时禁用动画。任务进行中刷新页面可读取当前任务恢复状态。状态查询或取消暂时断线时保留真实任务身份、继续查询／允许重试，不误判任务已失败或取消；原生 admission 丢失响应时同样保留任务并提供取消，不能自动再次产生付费请求。

回归需验证精确请求识别、原生 turn 隔离、普通 steer／历史不完整的保守展示、任务过程展开与收起、普通聊天不变、状态／取消／失败及减少动画。实际宿主渲染扩展需单独联调，不以合成宿主或单纯 API 正常替代原生组件验证。

## 8. 可编辑的白板使用方法（0.1.7-dev.1，2026-10-14）

### 8-A. 标准方法与边界

包内 `docs/board-guide.md` 是版本化的标准方法，指导普通白板写作与局部放置。一张卡围绕一个核心表达，长度服从独立理解需要；解释、依据、单位、条件、例外和来源放独立备注，备注也需提炼。主题层级用 parentChild，已有子卡换父用 reparent；需要显式边界的并列归组用集合，跨组依赖、支持、对比等用 association。公式仍是 text 节点，核心完整使用 `$...$` 或 `$$...$$`，说明放 caption。结构按需要使用，不能机械拆卡、重复标题或强制使用全部工具，不为精简删掉关键条件。随对话生长与布局优先的方法见 §10。

使用方法是模型的写作指导，不是自动压缩或重写已有卡片的算法；不能保证不同模型完全遵循。普通 read 工具补充核心／备注、父子边、换父和集合操作的载荷说明；数据与操作词汇仍以上游模型为真源，不复制一套执行规则。普通编辑可合理放置新内容并做必要局部调整；全板布局整理仍为独立受限任务。

### 8-B. 本地真源与注入

首次创建 `$DSH_HOME/dsh-board/board-guide.md`（dataDir 覆盖时位于该目录），为 UTF-8 Markdown；存在文件时不覆盖，包括自定义文本和空文件。升级只更新包内标准方法，不替换用户副本。用户可在设置页或本地编辑器读写该文件；不会把用户的副本打进安装包或写入 `.draft`。

固定协作协议保留为 dsh-board 提示节，使用方法作为独立 dsh-board-guide 节排在其后，文本与设置页有效说明一致。仅方法文本变化时替换该节，不重新注册稳定工具、不修改用户消息或旧历史、不注入时间戳／版本摘要。设置页保存立即更新后续模型请求；本地编辑约每 1.5 秒刷新，原生 Web 消息 admission 与白板读取前也刷新。已发给模型的请求不重写。

空文本或纯空白不注入写法建议，固定协作协议保留。关闭白板注销方法节，但管理页和文件仍可编辑；重新启用读取已保存方法。布局任务仍受本轮坐标工具范围及执行 guard 约束，方法文件不能扩大该权限。

### 8-C. 编辑、冲突与恢复

`GET /api/dsh-board/guide` 返回固定路径、最近有效文本、文件 revision、标准文本、大小上限、上一版路径及文件读取错误。`POST` 只接受 `{revision,text}`；客户端不能指定其他路径或改宿主配置。文本最多 16 KiB，拒绝空字符、非法 Unicode；读入须为有效 UTF-8，统一去掉开头 BOM、把 CRLF／CR 规范化为 LF。

保存用原文件字节摘要检查版本；不一致返回 HTTP 409／E_GUIDE_CONFLICT，保留当前文件及设置页草稿。写入在插件内串行，原子替换文件；替换前保留原字节到 board-guide.previous.md，并再次检查外部修改。此机制不宣称提供跨进程文件锁；本地编辑器与网页同时保存仍需核对版本。无变化保存不覆盖上一版。

文件无效、过大或无法读取时保留最近有效方法；启动时无有效版本则使用包内标准方法，并在设置页显示错误，编辑器明确展示的是最近有效说明。运行期间文件被移走／删除不会被轮询自动重建；用户保存可重新创建。过大文件须先在本地缩短，设置页不覆盖；非普通文件路径不覆盖。

编辑器未修改时跟随本地文件更新；有未保存文本时保留编辑并提示冲突，重新读取前提示先复制需要保留的内容。载入标准方法只填入编辑器，点击保存才写入并生效。正常刷新不能覆盖正在保存或主动重新读取的编辑状态。

### 8-D. 验证

回归覆盖首次创建、重启／升级保留用户副本、有效方法与用户可见文本一致、仅更新方法节、关闭与重新启用、空方法、UTF-8／大小边界、无效文件回退、外部修改冲突、上一版保留及固定路径。安装包检查从真实 tgz 加载实际设置组件，验证设置页保存、本地编辑反向同步、未保存草稿保护、标准方法预览与保存、提示节同步，并确认这些操作不改变白板修订号。

## 9. 草稿的流程外观（0.1.8-dev.2）

## 11. 普通 AI 编辑的自动几何预检（0.1.9-dev.1，2026-10-19）

### 11-A. 提交与渲染

## 12. 按聊天控制 AI 白板编辑权限（0.1.10-dev.1，2026-10-25）

### 12-A. 三态与作用域

输入框附近提供一个互斥三态选择器，直接显示当前状态；不另设含义重叠的自动维护开关。

| 用户可见状态 | mode | 新发送消息的白板权限 | 持续方式 |
| --- | --- | --- | --- |
| 本轮只聊 | `chat_once` | 可读取、讨论，不可修改内容或布局 | 下一条消息被宿主明确接收后，选择器恢复默认放权；该消息对应的响应继续只读 |
| 多轮只聊 | `chat_continuous` | 可读取、讨论，不可修改内容或布局 | 持续到用户手动切换状态 |
| 默认放权 | `auto` | AI 判断是否有必要维护白板 | 新聊天的默认状态；允许编辑不代表每轮必须修改 |

三态只作用于当前原生聊天，以 sessionId 区分；切换聊天显示各自状态，新聊天从默认放权开始。多轮只聊、默认放权及尚未消费的本轮只聊按聊天保存，刷新或重启后恢复。不同聊天虽然共用当前白板，消息的权限不能互相覆盖。

只聊限制该聊天对应响应中的 AI 写入；用户仍可手动编辑、保存、撤销和更换草稿。选区关联继续生效，只表示讨论对象，不构成编辑授权。其他聊天已获授权的 AI 仍可更新共同白板，因此只聊不等于锁定整张白板。

### 12-B. 消息绑定与状态转换

发送时冻结权限快照，通过原生 sessionId 与 admission requestId 绑定，与选区关联分别管理；关闭卡片关联不能关闭权限控制。用户正文、附件与既有历史保持原样，排队期间及之后切换选择器不能改写已提交消息的快照。

本轮指该原生用户消息对应的响应及其工具调用、重试、审批恢复和续跑，不等于一次模型请求或一个白板批次。一个只聊响应不能通过后续工具调用或续跑恢复写权限。

本轮只聊仅在原生 admission 明确接收后消费，不能在点击发送、暂存元数据或模型开始生成时提前消费。发送前失败或明确拒收保留该选择；响应丢失时保留原快照，等待原生恢复结果，不自动重发或假定未接收。消费按 requestId 幂等执行，不能覆盖用户在发送后新作的选择。

选择器的变化影响之后提交的消息，不追溯撤销已接收响应的授权或回滚已完成编辑。只聊消息通过 steer 注入正在运行的响应时，从被 claim 起收紧为只读，取消尚未到达文件提交点的 AI 写入；同一响应内后续消息不能再次放宽，结束后按下一轮绑定的快照重新判断。多个消息在同一原生响应中共同生效时，只要有一个只聊快照，该响应保持只读。

### 12-C. 权限数据与执行约束

权限子对象使用以下 v1 契约，外层消息身份取自原生 admission；模型不能自报 sessionId、requestId 或修改权限。该子对象不是白板 AgentBatch 的组成部分。

```json
{
  "type": "object",
  "required": ["version", "mode"],
  "properties": {
    "version": { "const": 1 },
    "mode": { "enum": ["chat_once", "chat_continuous", "auto"] }
  },
  "additionalProperties": false
}
```

宿主将 auto 解析为可按需编辑，其余两态解析为只读；运行上下文只提供当前有效权限说明，不注入卡片全文、时间戳或无关变化字段，不重写稳定系统提示与旧消息。只聊权限优先于方法文件和消息中要求写入的文字；若文字要求编辑，AI 说明需要先切换权限，不能自行解除限制。

程序在工具可见性、执行 guard、写入处理器及最终文件提交前检查权限，覆盖 draft_board_apply、draft_board_layout_apply 和 run_code 中的嵌套调用。只聊下拒绝 AI 白板写入并返回插件层 E_BOARD_READ_ONLY，草稿字节、宿主 revision、contentVersion 与历史不变；读取和白板以外的正常工具不受本功能限制。仍禁止通过 shell 或文件工具绕过白板编辑接口；本功能不宣称是操作系统文件访问隔离。

只聊状态下，AI 布局入口提示先切换默认放权，不隐式开启一次写权限。默认放权也不扩大布局任务原有的仅坐标权限，普通 AI 编辑仍须通过既有版本、原子批次与几何预检。人工 sync 不受 AI 只聊约束。

三态、消息快照和当前原生 turn 的有效权限保存在数据目录的 reply-permissions.json，不写入 .draft，不改变上游模型、文件格式或 batchVersion。旧版没有权限字段的聊天状态迁移为默认放权；旧的未绑定响应不因此获得写权限，须发送新消息。启用新协议后，缺失、非法或无法确认的消息权限不得默认为放权，必须拒绝 AI 写入并提供可恢复提示。

GET /api/dsh-board/permissions?sessionId=… 返回 {version:1,mode,revision}；POST 接受 {sessionId,mode,revision}，旧 revision 返回 HTTP 409／E_PERMISSION_CONFLICT。消息通过 association API 同时暂存独立 permission 子对象及 permissionRevision；重复 requestId 不允许更改快照。原生 inbox inserted／claimed 是消息已接收的证据，permissions/accepted 的 POST {sessionId,requestId} 供客户端在成功响应后幂等确认；确认通信失败不把已成功消息改判为发送失败。运行约束按原生 claim 提供的 turn 汇总，重启后恢复已保存的响应权限；每个 turn 的取消信号持续到原子文件重命名。

### 12-D. 行为验收与开发边界

```gherkin
Scenario: 本轮只聊只消费一次
  Given 当前聊天选择本轮只聊
  When 消息被原生 admission 明确接收
```

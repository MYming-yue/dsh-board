# DSH-board 规格

## 1. 项目边界

DSH-board 是 DSH web profile 的本地白板协作插件；draft-board 是白板界面、文件格式和模型的真源。插件从上游 `c37c6fe` 拆出，独立发布试用版 0.1.5。数据与交互契约沿用锁定的 [上游规格](https://github.com/MYming-yue/draft-board/blob/1c40d2ce857d39594b3fa70d5992f37ddc01ba69/docs/spec.md)。本项目不重复定义节点、关系、集合、操作和历史语义。

目标宿主为 DSH CLI 0.1.5-rc.1、组合包 0.1.5-rc.2、web profile；实际宿主联调为 Windows Chrome。其他组合未经完整验证。

## 2. 界面与消息

完整白板在左、原生对话在右；对话可收起，分隔线可通过鼠标或键盘调整宽度。布局通过 `shell.overlay` 添加，原生对话仍由 DSH 渲染；使用当前 AppFrame 中心列适配，不移动或接管其 React 节点。会话容器替换后重新挂接；中心列皮肤装饰限定在聊天区域。

发送瞬间捕获所选卡片的身份与至多 80 字符短标题，不附上正文／备注，不改写用户回复。通过原生 admission requestId 单独提交元数据；消息被 claim 时成为本轮关联，之后的选区变化不改写它。复用原生附件、echo、queue／steer 与取消流程。未关联的新回复清除旧关联，更换白板忽略旧身份。

固定说明在系统提示末尾，动态关联作为 `systemPrompt.context` 的末尾贡献，由 DSH 在已接受消息之后注入。关联无时间戳、修订号或模型可见消息 ID；相同关联文本一致，依赖原生快照去重。保留既有前缀与历史，不宣称零历史开销或固定缓存命中率。

## 3. 当前草稿与编辑

默认数据目录为 `DSH_HOME/dsh-board`，未设置 DSH_HOME 时使用 `~/.dsh/dsh-board`；宿主 composition 可用 dataDir 覆盖。`boards/<uuid>.draft` 保存 ZIP、内嵌资源与完整历史，`current.json` 指向当前文件。新开／切换聊天沿用当前草稿，白板“新建”／“打开”主动更换时保留旧文件。

`draft_board_read` 提供结构、文本与内容版本；`draft_board_apply` 接受 JSON 编码的上游 AgentBatch，使用真实身份、版本、原子校验与历史，不允许 shell 绕过。一个批次是一轮，既有更新标记与整轮撤销适用。图片资源保留，当前不新增图片视觉解析工具。

同源 API 约每 750ms 镜像已提交内容。浏览器快照携带进程代际和修订号，过期写入拒绝；输入、指针、布局、保存或回放期间保留操作。AI 更新保留视角，只有上游历史可验证的追加变化自动接收。冲突保留双方内容、暂停镜像，可另存为后重新打开副本明确更换。

宿主副本与原生磁盘文件句柄分别管理；AI 更新已绑定文件后仍显示未保存，不能将副本已更新当作原文件已保存。首次加载前阻止空白板编辑；嵌入模式不注册白板 Service Worker。

## 4. 管理

原生设置页入口“DSH-board 白板”，有 enabled 与 associateSelection 两项布尔选项。关闭共同白板恢复完整聊天布局、注销白板工具和提示；管理入口、草稿及隐藏页面的未提交输入保留。再次启用沿用当前草稿。关联选项变化不重新注册稳定工具或固定说明。

`plugin-state.json` 保存选项、待处理关联与当前关联，重启后恢复。关联元数据不写入 `.draft`，不形成独立任务系统。API 只允许修改插件自己的两项布尔选项，不修改 DSH 模型、凭据、MCP 或皮肤配置。

## 5. 独立构建与分发

upstream.json 保存公开上游 URL 与完整 40 字符提交 SHA。构建创建受管理的 `.upstream/draft-board` 缓存，核对远端、提交和目录边界；拒绝接管其他 checkout 或丢弃本地修改。依赖使用上游 package-lock.json；没有相邻目录或开发者磁盘路径依赖。

lib 包含上游编译的白板页面、共享模型、原生客户端适配、上游来源锁与许可证、运行依赖许可证声明。Release tgz 包含可运行产物，安装时无需重新获取或构建上游。源码仓库不提交生成的 lib、缓存、个人配置或草稿。

构建和打包不得读取个人 DSH home。更换上游提交需重新验证；修改白板业务语义应在上游实现，不在插件复制模型规则。插件拆仓库不改变原有 `.draft` 格式或数据目录。

## 6. 验证

`npm run check` 包含独立构建、Node 插件测试和安装包浏览器检查。测试覆盖批次原子性、版本与代际冲突、草稿切换／重启、消息正文保留、排队关联、稳定上下文、管理停用与保留草稿。

安装包检查用本次唯一临时目录和合成草稿，从真实 tgz 解压启动宿主 API，加载包内白板页面，接收批次并整轮撤销，验证包中不存在本地上游路径依赖。模型 API、真实 DSH 附件／审批和其他宿主版本仍需实际联调。任何失败或未验证范围应如实记录，不删断言制造通过。

## 7. AI 布局任务（0.1.6-dev.1，2026-10-12 开发预览）

### 7-A. 权限与目标

布局整理与卡片／关系／集合创建为独立任务。模型读取语义与现有结构，自主决定布局；提交仅包含已有卡片身份和坐标。禁止改变文字、备注、尺寸、颜色、展开状态、关系、集合成员及增删实体。

固定白板说明不随任务改变；仅在已接受的布局消息所属 Agent 本轮运行上下文尾部贡献布局专用规则。默认风格清晰、克制、留白适度：层级、对比、推导及跨组联系容易阅读，组内紧凑、组间留白、对齐有秩序、整体均衡，考虑窗口比例与可读性；保留合理现有布局，少做无意义移动。审美是软目标，范围、版本和几何为硬约束。卡片文字作为数据，不作为任务指令。

### 7-B. 原生任务接线

嵌入页面“AI 布局整理”普通点击为全板，Shift 点击为选中卡片及父子后代。页面先同步已提交内容，发送 boardId、baseContentVersion、宿主 revision、全板 DOM 实测外框、画布宽高及允许移动的身份列表。宿主客户端解析当前原生 SessionBinding，通过 Conversation.sendSession 提交一条明确的布局请求，附件列表为空，不消费原输入框的文字或待发附件，不另配 API、不创建隐藏模型服务。

布局快照单独 POST 至插件 API，用原生 sessionId 和 admission requestId 绑定；用户可见消息不附正文或几何 JSON。排队消息在 agent/inbox/claimed 时进入任务模式；只有匹配的 Agent 可以读取／提交。原生拒收则取消待处理任务；丢失响应时保留任务身份供查询或取消，不假定消息未被接受。

一个白板同时只允许一个 pending／running 布局任务，状态为 pending → running → completed／failed／cancelled。Agent 本轮工具可见性缩小为布局读取和提交，执行 guard 阻止其他工具调用；保留原生 run_code 传输，其嵌套调用仍经工具 guard。另一会话的普通编辑不受此工具掩码影响，但其内容更新会使旧布局版本失效。取消的排队请求被 claim 后仍受限制，不能通过通用编辑接口继续工作。

任务成功后本轮仍受限制，防止顺带修改内容。Agent idle／下一条原生用户消息结束任务模式并恢复普通工具；本轮未成功提交则标记失败。关闭插件取消任务并恢复原生工具流程。任务记录仅存内存，不写入草稿或插件状态；宿主重启后旧任务不可提交。恢复的原生工具栏请求若没有对应快照，本轮仍限制为布局工具，提示重新整理，不能回退到通用编辑。

### 7-C. 受限工具与候选校验

`draft_board_layout_read` 参数为空，只对当前布局 Agent 返回 taskId、boardId、baseContentVersion、允许移动的 nodeIds、全板内容／边／集合、geometry、viewport 和剩余尝试次数。

`draft_board_layout_apply` 仅接受 `{taskId, boardId, baseContentVersion, positions:[{nodeId,x,y}]}`。拒绝额外字段、重复或超范围身份、非有限坐标及绝对值超过 10,000,000 的坐标。原生运行身份决定任务归属，不接受调用方自报会话身份。

候选先在内存中用上游原子批次应用为 moveNode，再用共享几何检查卡片至少 10 世界单位间距、非成员卡片与集合边界、自动绕行后连线与非端点卡片及关系说明遮挡。局部任务忽略完全不涉及允许移动卡片的旧冲突。失败返回具体冲突和剩余次数，不修改文件、修订号或历史；最多 3 次候选尝试。所有有效移动同一步提交，沿用真实 before、版本递增与整轮撤销。空或实际无变化的 positions 直接完成且不新增历史。

白板更新、身份／内容版本／进程修订变化拒绝旧候选；卡片显示外框或画布宽高相对任务快照变化，经页面约 750ms 报告后使任务失效。版本与布局提交共用串行写入队列。取消信号在原子文件重命名前生效；重命名已完成即视为提交成功，随后完成指针与内存发布，不制造已落盘而内存未更新的状态。

`E_LAYOUT_TASK`、`E_LAYOUT_GEOMETRY` 是插件任务层结果，不增加上游模型错误码。正文编辑继续使用原有 `draft_board_read`／`draft_board_apply`，不复用布局提交入口。

### 7-D. 验证

单测覆盖 admission 身份、拒收与丢失响应、任务工具范围与退出、局部范围、非法字段／坐标、候选失败不落盘、三次上限、并行版本变化、显示变化、取消排队任务、无变化无历史与单批提交。解压安装包浏览器检查验证实际尺寸快照、宿主桥接、受限提交、镜像接收和一次撤销。真实 DSH 还需验证当前对话绑定、工具 guard／掩码与实际模型输出；审美质量由用户测试反馈继续迭代，不以合成宿主回归宣称保证。
